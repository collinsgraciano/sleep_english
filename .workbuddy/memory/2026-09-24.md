## 新建 skill：sleep-script-batch（批量生成「睡觉听英语」视频脚本）
- 用户要求：先做一个可复用 skill，再用它批量生成 100 个不重复热门主题的对话脚本，存到文件夹，可直接用于生成视频。
- 位置：`.workbuddy/skills/sleep-script-batch/`（项目级 skill）
  - `SKILL.md`：用途/触发/运行方式/消费方式说明
  - `scripts/generate_sleep_scripts.py`：核心生成器
- 原理（离线、零积分、确定性）：
  - 36 个 A/B 模板帧（`{x}` 占位，`v`=动词短语 / `t`=主题名词）+ 29 类动词库（来自 pipeline/topics.json 分类）+ 100 个跨类不重复主题。
  - 每主题生成 200 组 A/B = 400 行 dialogue；`char_a`=男声 / `char_b`=女声交替（与 pipeline 的 rows[0::2]/[1::2] 一致）。
  - 音标用 `eng_to_ipa`，中文用 `opencc`(s2t) 转繁体，匹配频道繁中规范。
  - 输出与 pipeline 完全兼容：每个主题一个运行目录（含 script.json + images/audio/clips/subtitles/videos + checkpoint.json 标记 step0_script 完成），可被 `python pipeline.py --resume` 或 Web「批量脚本入库」直接续跑生成视频。
- 关键经验：
  - `eng_to_ipa` 逐句调用很慢（4 万句约 10+ 分钟会触发超时）；已加进程内 `_IPA_CACHE` 字典缓存，重复句子只算一次，整批 100 个 ~ 1 分钟内完成。
  - 模板帧里 `I'm {x}.` 等接动词短语会语法错误，已改为 `I'm here to {x}.` 等；主题帧用 `My favorite is {x}.` 等避免 "common phrases for X" 类别扭句。
- 运行命令（用隔离 venv python）：
  `C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe .workbuddy/skills/sleep-script-batch/scripts/generate_sleep_scripts.py --out batch_scripts --count 100 --lines 400`
- 输出：`batch_scripts/001_.../` ~ `100_.../` 各含 script.json，根目录 `manifest.json` 记录清单。

## 项目要点补充

- TTS 只读 `script["dialogue"]`，奇偶行分男女声；消费路径 `_seed_from_script_library` 读 configs/script_library/{id}.json 注入运行目录。

## 重要更正：sleep-script-batch 已改为「真 AI 生成」模式
- 用户明确否决了 Python 模板套词方案，要求**每个主题都用 AI 重新生成完整相关内容**。
- 生成器已改为调用项目自带 `pipeline/sleep/llm_client_sleep.generate_sleep_script(topic, cefr="A2", num_pairs=200, batch_pairs=50, use_cache=False)`（SenseNova deepseek-v4-flash，凭证从 configs/default.json 注入环境变量）。
- 冒烟测试 + 首个主题验证均通过：产出 400 行、speaker 交替、繁中 youtube 标题、音标 IPA，内容确为主题专属（非模板）。
- 已加**自动续跑**：每个主题生成前若其运行目录已有通过校验且 topic 匹配的 script.json 则跳过，中断后重跑同命令即从断点继续、不浪费 LLM 额度。
- **safe-delete 坑**：本工作区的 safe-delete 防护会拦截对 `batch_scripts` 等项目的 `rm -rf`/`shutil.rmtree`（报 trash-failed），导致删不干净、旧模板脚本残留。
  - 解法：重跑时直接把 `--out` 指向**全新目录**（本次用 `ai_scripts`），既绕过防护，又避免续跑跳过逻辑误保留旧模板脚本。
- 当前进度：全量 100 主题 AI 生成已启动到 `ai_scripts/`（后台任务），首个主题 `001_Making_Breakfast` 已验证 OK；整批约 ~10h（每主题≈6min，含偶发 429 限速重试）。旧的 `batch_scripts/`（模板版残留）仍可手动删除。

## ⚠️ 关键坑：LLM 凭证在 agent 执行环境里「时有时无」
- 实测：`configs/default.json` 里**只有** `llm_provider=sensenova` + `llm_min_interval`，**完全没有** base url / api key / model（sensenova_base、sensenova_base_url、sensenova_api_key、sensenova_model 全不存在于 config 与 env）。
- 用户的真实 LLM 凭证（OPENAI_BASE_URL / OPENAI_API_KEY / OPENAI_MODEL，指向 sensenova 的 openai 兼容端点）由 WorkBuddy 运行时**临时注入**到后台任务的 env；第一批 92 个能成是因为那时 env 里有凭证，之后消失（沙箱也不让我读/设密钥）。
- `_chat`(llm_client.py) 只有 `wbk/gemini/openai` 三个分支、没有 `sensenova` 分支；`llm_provider=sensenova` 会落到 openai 分支读 `OPENAI_BASE_URL`。凭证缺失时空串拼出 `/chat/completions` → 报 `unknown url type`。
- 已修复生成器 `_load_llm_env`：从「env + config」多来源收集 sensenova/openai 凭证并强制映射成 `OPENAI_*`，并加「无 openai 且无 wbk 凭证时清晰报错并 sys.exit(2)」的前置检查；另加 wbk 退回（WBK_BASE_URL 硬编码）。
- 结果：当前环境**完全无 LLM 凭证**（openai/sensenova/wbk 全 false），故 8 个主题（006/007/014/015/019/029/033/077，恰好是模型返回句数不足/被截断的难生成主题）暂无法补齐。
- 续跑方式（凭证可用时）：重跑 `.../generate_sleep_scripts.py --out ai_scripts --count 100 --start 0 --lines 400`；skip-if-valid 自动跳过已成功的 92 个、只重做这 8 个。当前状态：ai_scripts/ 下 100 个文件夹中 **92 个有效**（400 行、schema 全过），8 个缺 script.json。
